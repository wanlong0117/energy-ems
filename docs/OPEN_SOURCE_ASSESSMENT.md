# energy-ems 开源可行性评估

> 评估日期：2026-11-26 ｜ 评估对象：`wanlong0117/energy-ems`
>
> 本文件是开源化前的评估记录；末尾「8. 现状复核」按 v0.1.4 更新了各项数字，两者不一致时以复核表为准。
> 结论先行：**可行，最终采用 MIT 许可开源**（评估时曾推荐 Apache-2.0，出于简化与传播考虑改为 MIT），但必须先补齐 6 项「开箱可用」门槛，否则会沦为代码托管。

---

## 1. 结论

| 维度 | 判断 | 说明 |
|---|---|---|
| 技术可行性 | ✅ 高 | 单进程 + SQLite，零外部服务，Windows 绿色包可直接跑 |
| 许可合规 | ✅ 干净 | 全部依赖为 MIT/BSD，未见 AGPL 代码复制；PyInstaller 有打包例外 |
| 市场空位 | ✅ 存在 | MyEMS 重、OpenEMS 陡、ThingsBoard 不垂直，缺「Windows 小厂即装即用」 |
| 维护可持续性 | ⚠️ 中 | 当前单人维护，issue/PR 吞吐是最大风险 |
| 商业化潜力 | ⚠️ 中 | 实施/定制可收费，纯软件订阅难 |
| 现在直接开源 | ❌ 不建议 | README 仅 1 行、无 LICENSE、默认密码硬编码、无安全说明 |

**一句话**：项目本身够格开源，但「开源工程化」还没做。补齐门槛约需 1~2 周，之后可以发 v0.1.0。

## 3. 许可合规

### 3.1 依赖许可

| 依赖 | 许可证 | 与 MIT 兼容 | 备注 |
|---|---|---|---|
| FastAPI | MIT | ✅ | |
| Uvicorn | BSD-3-Clause | ✅ | |
| Pydantic | MIT | ✅ | |
| openpyxl | MIT | ✅ | |
| reportlab | BSD-3-Clause | ✅ | 商用需注意其字体授权（用 CID 字体，未内嵌商业字体） |
| pyserial | BSD-3-Clause | ✅ | |
| PyInstaller | GPL-2.0-or-later **with bootloader exception** | ✅ | 打包产物可闭源/任意许可分发；已在 THIRD_PARTY_NOTICES 说明 |

### 3.2 代码来源

- 采集层为自研（MBAP、CRC16、串口），**未使用 pymodbus**，无 GPL 传染风险。
- 未复制 MyEMS / OpenEMS / Emoncms 代码，仅参考功能设计，**不构成 AGPL 派生作品**。
- 需保留一份 `THIRD_PARTY_NOTICES.md`，列明依赖与许可，避免下游合规疑问。

### 3.3 许可证选择建议

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **MIT（已采用）** | 最短、传播最快、商用无摩擦、与依赖全兼容 | 无明示专利条款 | 最大化 star 与试用 |
| Apache-2.0 | 专利授权、企业法务偏好、可闭源集成 | 比 MIT 长，需 NOTICE | 想被大型集成商采用 |
| AGPL-3.0 | 强制回馈 | 吓退集成商，和「替代 MyEMS」定位冲突 | 不推荐 |

> 决策：**MIT + THIRD_PARTY_NOTICES**。理由：本项目定位是「让最多人装上、跑起来」，
> MIT 的零摩擦胜过专利条款；专利风险可通过 issue 与贡献者协议在长期演进中再补。
> 若日后出现企业级集成需求，可评估双许可（MIT + 商业）。

## 4. 竞品格局

| 项目 | 许可证 | 技术栈 | 部署重量 | 强项 | 弱点 |
|---|---|---|---|---|---|
| MyEMS | AGPL-3.0 | Python/Django + Vue + MySQL/Redis/MQ | 重 | 功能全、行业案例多 | 部署运维门槛高、二次开发重 |
| OpenEMS | AGPL-3.0 | Java/OSGi | 重 | 工业级、边缘控制 | 学习曲线陡、文档偏开发者 |
| Emoncms | AGPL-3.0 | PHP + MySQL | 中 | 家庭/社区能源监测 | 工业协议与报表弱 |
| ThingsBoard | Apache-2.0 | Java | 中 | 通用 IoT、可视化强 | 非能源垂直，计量口径要自建 |
| Home Assistant | Apache-2.0 | Python | 轻 | 家庭自动化生态 | 非工业计量/报表 |
| **energy-ems** | 待定 | Python 单进程 + SQLite | **极轻** | Windows 绿色包、Modbus 三协议、中文报表、零运维 | 功能广度、生态、多人协作 |

**空位**：中小工厂/园区/物业，Windows 环境、无专职 IT、几十到几百块表、只需要「看数 + 出报表 + 接 Modbus」。这类用户装不动 MyEMS，也不需要 OpenEMS。

## 5. 开源前必须补齐（P0，1~2 周）

| # | 事项 | 现状 | 完成标准 |
|---|---|---|---|
| 1 | LICENSE | 无 | 根目录 MIT 全文（含版权行）+ README 徽章 |
| 2 | README 重写 | 1 行 | 截图、特性、5 分钟快速开始、架构图、FAQ、免责声明 |
| 3 | 默认密码安全 | `ems2026` 硬编码 | 首次登录强制改密；文档红字提示；支持环境变量覆盖 |
| 4 | 仓库卫生 | `config.json` 未忽略 | `.gitignore` 补 `config.json`、`*.db*`；确认无密钥/内网 IP |
| 5 | SECURITY.md | 无 | 漏洞上报渠道、支持版本、响应时限 |
| 6 | CI 跑测试 | 仅 build-windows | push/PR 触发 `pytest` + 依赖缓存；badge 展示 |

### P1（1~2 个月）

- Dockerfile + compose（Linux/NAS 用户，极空间/群晖场景）
- CONTRIBUTING.md、Issue/PR 模板、CODE_OF_CONDUCT
- CHANGELOG + 语义化版本（先 v0.1.0）
- 多用户 + 角色权限（当前单密码，多人用会互相覆盖）
- 告警通知（邮件/企微/钉钉），这是企业刚需
- OpenAPI 文档对外（FastAPI `/docs` 默认已有，补鉴权说明）
- 性能基准：100 表 / 5 分钟采集 / 报表 1 年数据

### P2（3~6 个月）

- 插件式协议（MQTT、OPC UA、BACnet）
- 多租户 / 多站点
- 演示站点（脱敏数据）或一键 demo 容器
- 移动端适配深化（当前已响应式，但表格体验一般）

## 6. 社区增长路径

1. **先做「可复现」**：README 里的 5 分钟流程必须在干净 Win11 上录屏验证，成功率 > 90%。
2. **中文优先**：公众号/知乎/B站发「用 Python 写一个替代 MyEMS 的轻量 EMS」系列，附真实截图和 exe 下载。
3. **行业群渗透**：暖通、物业、小型制造群，痛点明确（报表、Modbus 对接）。
4. **GitHub 运营**：good-first-issue、讨论区、每月 release notes；不要买 star。
5. **不要过早做官网**：先把 README 和 issue 响应做好，转化率比官网高。

## 7. 商业化路径（可选）

| 模式 | 说明 | 可行性 |
|---|---|---|
| 实施/部署服务 | 现场 Modbus 点位调试、报表定制 | 高，客单价 5k~5w |
| 定制开发 | 对接企业 ERP/能源平台 | 高 |
| 软硬一体 | 预装 EMS 的工控机/网关 | 中高，需硬件供应链 |
| 企业版订阅 | 多用户、告警、SLA、审计 | 中，需先补齐 P1 |
| 托管 SaaS | 多租户云 | 低（数据合规、运维成本） |

**建议**：开源核心 + 付费实施，是最现实的路径；不要一开始做订阅制。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 单人维护（bus factor=1） | 高 | 把架构/部署写成文档；培养 1~2 个核心贡献者；issue 模板降低沟通成本 |
| 安全漏洞（默认密码、无 TLS） | 高 | 首登改密、反向代理 TLS 指南、SECURITY.md、依赖扫描 |
| 功能广度被 MyEMS 碾压 | 中 | 不拼功能，拼「装得快、改得动、报表准」 |
| AGPL 代码污染质疑 | 中 | 保留开发记录、THIRD_PARTY_NOTICES、声明未复制 |
| PyInstaller 被误判 GPL | 低 | THIRD_PARTY_NOTICES 写明 bootloader exception |
| 商标风险 | 低 | 宣传中不使用 MyEMS 名义；「兼容/替代」表述改为「可迁移」 |
| 现场协议差异（字节序/寄存器） | 中 | 试读工具 + 字节序对照已具备，补现场案例库 |

## 10. 最终建议

1. **开源，但按「产品发布」标准做，不要按「代码备份」标准做。**
2. 许可证已定为 **MIT**（见根目录 LICENSE）；不要 AGPL。
3. 先花 1~2 周补齐 P0 六项，再公开宣传；否则第一波流量会变成「装不上」的差评。
4. 定位一句话：**「一块工控机就能跑的轻量能源管理系统，Modbus 直连，中文报表，零运维。」**
5. 短期内不要追求功能对齐 MyEMS，先把「100 块表、1 年数据、5 分钟装好」这三件事做到无可挑剔。
